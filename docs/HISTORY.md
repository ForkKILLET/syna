## 0.2 – 0.4 — the tarball baselines

Before this repository Syna was delivered as source archives. 0.3.0 introduced the refined package-scoped API and the first executable implementation of the frozen Syna Core Semantic Model v0; 0.4.0 split the core into the definition registry, resolution realms, graph builder, entry planner, materializer, bounded plan cache and implementation directory, added `override()`, private resolution realms, `loadAll()`, `Symbol.asyncDispose`, topology preflight and an adversarial suite of 88 runtime tests (the 0.4.0 entry of `CHANGELOG.md` lists the rest). The 0.4.0 archive, `syna-v0.4.0-source.tar.gz` (sha256 `e0f21a94765aeb9f8e9e7987d596844e4d1bf56fce3584c8de1358131f42a96c`), is the first commit of this repository, `de1d441` (2026-09-04): its changelog with the 0.3.0 and 0.4.0 entries, its READMEs, its own validation record and its benchmark records — `benchmarks/results-v0.3.0.json` and `benchmarks/results-v0.4.0.json`, while `benchmarks/results-v0.4.0-baseline-same-machine.json` is the 0.4.0 workload re-run on the 0.5 machine for `docs/VALIDATION.md`'s v0.4 comparison. Nothing of 0.2 survives here beyond that changelog's reference to the earlier line. An earlier prototype of the idea, an April 2026 context-proxy experiment of eleven commits, is kept on `github.com/synajs/syna` as the branch `legacy/context-proxy` and the tag `archive/2026-04-context-proxy`; it is not a baseline of any release recorded here.

## 0.5.0 — the application-driven kernel（应用驱动）

Task book `SYNA_V05_EXECUTION_PROMPT.md` (goal `SYNA_V05_GOAL.txt`). Hyla-mini, a narrow but complete multi-tenant blog engine — real PostgreSQL and real filesystem backends × dynamic HTTP and static builds, three Markdown recipes sharing one set of remark/rehype factory slots, two tenants with domain mapping and replaceable authentication, a bounded and leased SiteEnv working set — was built first and drove the kernel: plain-Promise loads without a setup barrier, attempts, waiters and deadlines, Ready-anchored bound Entries, private realms, compiled overrides, `explain()`, npm semver; the R01–R20 counter-example suites and the reference planner differential; three review rounds and independent fresh-context audits with executable probes (`docs/AUDIT.md`, `docs/audit/`); the transparent gate `scripts/verify-v05.mjs` (archive, rebuild from the archive, pack, consumer smoke, manifest). Records: `docs/SEMANTIC_CHANGES_V05.md` (what is kept from Semantic Model v0 and what was revised, each item with its test) and `docs/MIGRATION_V04_TO_V05.md` (M-01 …). Final gate COMPLETE on e174c57, evidence 2407af3 (`work/v05/STATE.md`). The 0.5 line was pushed to `github.com/synajs/syna-v05`, the workspace's home before `github.com/synajs/syna`, where the CI release-gate job had its first cloud run.

## 0.6.0 — API consolidation（改名）

Task book `work/tasks/SYNA_V06_API_EXECUTION_PROMPT.md` (goal `work/tasks/SYNA_V06_GOAL.txt`). Names and types only, semantics verbatim 0.5: six renames with one-minor `@deprecated` aliases (`scope` → `reuse`, `bind` → `anchor`, `SynaRuntime` → `Runtime`, `DependencyRef` → `ServiceRef`, `PersistentImplementationRef` → `ImplementationRef`, `context.site` → `dependencySite`), deletions and merges, type strengthening; the zero-semantics guards that every later round kept — the 0.5.0 check/explain/inspect/catalog/error snapshots, the reference planner differential, the same-machine benchmark medians, the per-file `any` budget — and the public API inventory tool `scripts/api-inventory.mjs` with its diff. Record: `docs/MIGRATION_V05_TO_V06.md` (with the note that the serialized key was later kept permanently and then removed in 0.8). Final gate COMPLETE on f019402, evidence 582c93a (`work/v06/STATE.md`).

## 0.7.0 — expiry and semantic revision（语义修订）

Task book `work/tasks/SYNA_V07_EXECUTION_PROMPT.md` (goal `work/tasks/SYNA_V07_GOAL.txt`), with a written proposal reviewed before implementation (`work/v07/PROPOSAL.md`). The 23 aliases of 0.6 and the 0.5 call form removed, the selector's last remnants deleted, the error codes split by throw site and meaning (S6, S7) with one `INVALID_DESCRIPTOR` shape and the `MISSING_IMPLEMENTATION` shapes (S8), `asSynaError()` (S10); two semantic revisions — S1, the load deadline is the waiter's timeout, not the attempt's; S2, `env.state` advances only by Runtime actions and what outlives a close is accounted for in the attempt ledger — and the one timer for all waiters that became the `DeadlineQueue`. Records: `docs/SEMANTIC_CHANGES_V07.md` (kept / clarified / revised / withdrawn, every rewritten or deleted test registered) and `docs/MIGRATION_V06_TO_V07.md`. Final gate COMPLETE on 1abe595, evidence 72f1991 (`work/v07/STATE.md`).

## 0.8.0 — the last rename（最终收束）

Task book `work/tasks/SYNA_V08_EXECUTION_PROMPT.md` (goal `work/tasks/SYNA_V08_GOAL.txt`). The last rename before 1.0, names only: types (`Env`, `Entry`, `ImplementationRecord`, `NodePlacement`, `InputValue`, `SlotState`), fields and parameters, values and events, two structures (`derive(options)`, `catalog.revisions(family)`); no alias, no old key — the 0.5 serialized key and its read path deleted, one shape of `ImplementationRef` — and no semantic change, asserted by the snapshots and the planner differential; the codemod `scripts/codemod-v08.mjs` migrated every consumer and is idempotent over the tree; the inventory diff against 0.7.0 is exactly the rename table (`work/v08/RENAME_TABLE.md`). `docs/API_STABILITY.md` declares the public surface frozen from 0.8.0: no compatibility promise before 1.0, changed only by a major from 1.0 on. Records: `docs/MIGRATION_V07_TO_V08.md`, `docs/GLOSSARY.md`. Final gate COMPLETE on 38a722e, evidence e24859f (`work/v08/STATE.md`).

## 1.0.0-rc.2 — the examples rebuilt（示例重建）

Task book `work/tasks/SYNA_RC2_EXECUTION_PROMPT.md` (goal `work/tasks/SYNA_RC2_GOAL.txt`; plan and coverage proof `work/rc2/DEMO_PLAN.md`, `work/rc2/COVERAGE_CHECK.md`). No change of the core again: the inventory identical to the 0.8.0 record and to the 1.0.0-rc.1 record, the planner differential and the snapshots unchanged. The four demos that had grown with the kernel — `apps/minimal-demo`, `apps/features-demo`, `apps/hyla-demo`, `apps/fluida-demo`, with the fixture packages `llm-contract`, `openai-v1` / `openai-v2`, `claude`, `hyla`, `fluida`, `postgres` and the old `logger` — were replaced by seven progressive examples in one fictional domain, a multi-tenant notification delivery service (`apps/01-basics` … `apps/07-failure-modes`; `docs/EXAMPLES.md`, which also records the naming rule and that the examples are where the manual's snippets come from), and by fixtures with fictional vendor names (`notify-contract`, `acme-notify-v1` / `acme-notify-v2`, `globex-notify`, `tenant-store`, `logger`). Where the four went: `minimal-demo` → `01-basics`; `hyla-demo` (a stored provider choice, two revisions of one Family, the catalog) → `03-user-configurable` and `04-two-versions`; `fluida-demo` (a Service opening its own child worlds through an AnchoredEntry) → `05-scheduled-jobs`; `features-demo` (eager start during Entry activation, destructured references still lazy, a structural cycle callable after setup, a setup wait cycle refused) → the core tests named in `work/rc2/COVERAGE_CHECK.md` and, for the wait cycle, `07-failure-modes`. The reference application Hyla-mini (`apps/hyla-mini`, `@hyla/mini`, `docs/HYLA_MINI.md`) was renamed multitenant-blog (`apps/multitenant-blog`, `@syna-app/multitenant-blog`, `docs/MULTITENANT_BLOG.md`) with no change of behaviour: its `syna.id` `hyla.mini`, its schema default, its advisory-lock namespaces, its log prefixes and its static-build manifest tag are what they were; the sections above, the ledgers and the recorded evidence keep the old name. The release gate gained a step per example, the `blog-*` steps, the diff against the 1.0.0-rc.1 record and the vendor-name scan. Record: `CHANGELOG.md`; evidence `validation/v1.0.0-rc.2-release/`, `work/rc2/STATE.md`.
