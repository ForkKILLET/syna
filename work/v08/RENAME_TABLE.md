## F3 — the complete `*Key` list

Public surface (`grep 'Key\b'` over `work/v08/API_INVENTORY_BEFORE.md`): two fields carry a revision id under a `*Key` name — `RuntimePolicyContext.parentActiveRevisionKeys` (F2 → `parentActiveRevisionIds`) and `INVALID_INHERITED_CHOICE.details.selectedKey` (F3 → `selectedRevision`). `ServiceRevision.key` itself is F1. The other `Key` matches in the inventory are mapped-type parameters (`[Key in keyof …]` in `DependencyRefs`, `LoadedDependencies`), not fields. `CandidateRef` (public) has no `*Key` field (`{ kind, contract, familyId, version }`).

Internal identifiers that end in `Key` stay as they are (they are not public names; renaming them is churn without a reader): `CompiledService.key`, `InternalCandidateRef.revisionKey`, `RevisionLike.key` (identity.ts — it *reads* `ServiceRevision.key` and follows F1 as `id`), `ResolutionRealm.ownerKey` / `closureKeys`, `rootSiteByEntryKey`, `lineageKey`, `templateKey` / `planTemplateKey`, `byRevisionKey`, `byKey`, `sourceKey`, `activeRevisionKeys` (RuntimeImpl; it feeds `parentActiveRevisionIds`), `compiledByKey`, `originalKeys` / `orderedKeys` / `allowedKeys` / `activeKeys` (local variables). `LEGACY_KEY_MARKER` / `LEGACY_FAMILY_KEY` / `legacyKey` are deleted by F9.

## Decisions taken in Phase A (recorded before any code changes)

1. **F9 changes the error class of `parse()`.** 0.7 `Binding.parse()` / `parseImplementationRef()` throw plain `TypeError`s for every invalid input (`A persistent implementation reference must be an object.`, `Invalid persistent implementation reference for Contract X.`); the 0.5 snapshot records two of them (`errors.parseWithoutId`, `errors.parseForeignContract`). F9 and A05 prescribe `INVALID_DESCRIPTOR` for everything the read path refuses, so `parse()` throws `SynaError('INVALID_DESCRIPTOR')` with the 0.7 S7 details shape `{ descriptor: 'ImplementationRef', problem }`: `not-an-object` (existing token) for a non-object, `wrong-kind` (existing token) for any other `kind` (the old literal included), and one new token `malformed-implementation-ref` for a missing or empty `familyId`, a missing, empty or invalid `range`, or another Contract's id. Trigger conditions are the 0.7 ones; only the class and the message wording change. The snapshot test maps the two recorded errors (`RENAMED.values` for `name` and `message`, `ADDED` for `code` and `details`) so the recorded data stays untouched; the mapping is the only zero-semantics guard that changes for this item. This is the one place where §2 is more than a rename, and it is prescribed by §2.2 F9 / §4 A05 — reported here rather than stopped on.
2. **F15 covers the details fields.** `attempt: number` also appears in `SynaErrorDetails.INITIALIZATION_TIMEOUT` (→ `LOAD_TIMEOUT`) and `LIFECYCLE_MISUSE`; it is the same number the event and the ledger report for the same attempt, so it becomes `attemptNumber` there too (renaming only the event and the ledger would leave `error.details.attempt === event.attemptNumber`). Listed under F15 above.
3. **Benchmark records across the rename.** `benchmarks/v0.5-planning.mjs` spreads `explanation.services` and `inspect().planCache` into its output, so a 0.8 run records `reused` / `eagerReused` / `limit` where the 0.7.0 side records `inherited` / `eagerInherited` / `maxEntries`. `scripts/benchmark-compare.mjs` normalizes both sides to the 0.8 keys before comparing (the only key rename of the record format; the benchmark's own top-level `inherited` key is its own name and stays), so the same-session comparison against 0.7.0 and the record-drift comparison keep every counter (`116/116 equal` remains the criterion). No benchmark number changes.
4. **Hyla-mini's own names.** The application's `cacheStats.maxEntries`, `PipelineBuilder.stats.maxEntries`, `pageCacheMaxEntries`, the `mustInherit` budget option and its "must be inherited" wording, and the `describeCause` fallback text are Hyla-mini vocabulary, not Syna's (§2 renames Syna's `planCache.maxEntries` and the placement value); they stay. Hyla-mini's `BudgetReport.forks[].disposition` mirrors `ExplainedNode.disposition` and is renamed along with it (the codemod's F13 token).
5. **What the codemod cannot do, and what is done by hand in Phase C** (each recorded in `work/v08/STATE.md`): delete the old-key code (`apps/hyla-mini/src/domain/recipe-schema.ts` schema branch + `normalizeStoredImplementationRef`, `packages/core/tests/v07-legacy-implementation-key.test.mjs`, `apps/hyla-mini/tests/v06-compat.test.mjs`, the legacy-form case of `v07-s8-missing-implementation.test.mjs` which becomes the F9 `INVALID_DESCRIPTOR` case); `runtime.catalog.revisions('snap-db')` → `revisions(Db1.family)` in the snapshot test (S2 needs the descriptor; the codemod reports the site); the snapshot test's `RENAMED` / `ADDED` mapping (frozen for the codemod with `codemod-v08: off/on`, rewritten by the §2 mapping); assertions on key lists (`Object.keys(candidate)` in `v07-expired-forms.test.mjs`: `ref` → `candidateRef`, `persistentRef` → `implementationRef`, re-sorted); the gate tooling (`scripts/verify-v08.mjs`, `benchmark-compare.mjs` normalization, the `no-old-names` / `api-inventory` test tables).

6. **An expired 0.7 form the Runtime can read is refused, never ignored** (Phase C; `docs/MIGRATION_V07_TO_V08.md` §0). Four renamed forms would otherwise be read silently as "nothing": `define.service({ setupDeadlineMs })` (an unbounded load), `define.service({ metadata })` (an unlabelled family), `limits: { setupDeadlineMs }` (the default timeout), `env.derive({ fresh })` / `({ share })` (an unconstrained child world; the 0.7 `derive(constraints)` form) and `catalog.revisions(familyId)` (an empty list). They are refused naming the current form — `TypeError`s, and `INVALID_DESCRIPTOR` (`ServiceFamily`, `not-an-object` / `wrong-kind`) for the catalog — exactly as 0.7 refused the definition-time `scope`, the call-time `scope` and the nested limit records. No new public name, no new option; two new `INVALID_DESCRIPTOR` throw sites (36 in the S7 table). Every other 0.7 spelling is a compile error, an absent property or a comparison that never holds — the codemod and `tsc` find those. Test: `packages/core/tests/v08-expired-forms.test.mjs`; the marked lines that spell the old names in the core are the two refusal sites (`syna-v08-rename`).
