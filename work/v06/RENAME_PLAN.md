# Syna v0.6 — API consolidation: rename plan

Source of truth: `SYNA_V06_API_EXECUTION_PROMPT.md` §3 (the only list of names). Baseline inventory: `work/v06/API_INVENTORY_BEFORE.md` (generated by `node scripts/api-inventory.mjs` on 0.5.0: 104 exports, 249 members, 42 union members, 5 `@deprecated` items). The "reason" column refers to §2: **(1)** the name collides with Syna's own vocabulary, **(2)** the name collides with the industry meaning, **(3)** one concept carries several names.

Occurrence counts below come from `grep -rcE` over `packages`, `apps`, `benchmarks`, `scripts`, `docs`, the READMEs and the CHANGELOG (excluding `node_modules`, `dist`, `docs/audit`, `work/*/probes`), taken on 0.5.0 (commit 4a67b99) before any change.

## Ground rules applied to every item

- One commit per item. An R commit carries the new name, the `@deprecated` alias (JSDoc points at the new name and names the removal version 0.7.0), a migration test asserting old and new are behaviourally identical, a type test asserting the old name still compiles and is flagged deprecated, and the documentation for that name. D/M/T commits carry their tests and docs the same way.
- Aliases are runtime-equivalent: the same function object where possible, otherwise a forwarding getter over the same frozen data. No third name, no behaviour change, and the alias path runs every check the new path runs.
- Names outside §3 stay untouched. Anything that looks wrong along the way goes to `docs/DEFERRED.md` ("命名" or "语义"), not into the code.
- Zero-semantics guards, all recorded on 0.5.0 **before** the first rename commit: `packages/core/tests/v06-snapshots.test.mjs` (check/explain/inspect/catalog/error snapshots; the test's `RENAMED` mapping is the only thing a rename commit may touch there), the `reference-planner.test.mjs` differential, `benchmarks/results-v0.5.0-baseline-same-machine.json` (median of 7 runs) compared by `scripts/benchmark-compare.mjs` (±10 % p50/p95, cache counters equal), the per-file `any` baseline in `work/v06/ANY_BASELINE.json`.
- Apps, demos, benchmarks and scripts are migrated to the new names (Phase D); the grep test `scripts/tests/no-old-names.test.mjs` fails on any old name there.

## Findings recorded before implementation (§1: keep the old behaviour, record, do not "fix")

| # | Item | Finding | Decision |

## R items (§3.1)

### R1 `scope` → `reuse`; call-time constraints move to a separate `options` record — reason 2 (+ `args.scope` collides with an Input named `scope`)

Shape after the change: `enter/check/explain(entry, args?, options?)`; `run(entry, args?, options?, callback)` with the callback always last; `options.reuse` is the only call-time constraint entry; `derive(options)` takes `ReuseConstraints` directly (unchanged shape, renamed type).

| Old | New | Alias |
|---|---|---|
| `EntryDefinition.scope` | `EntryDefinition.reuse` | `scope` accepted, deprecated; both given → `TypeError` |
| `EntryDescriptor.scope` | `EntryDescriptor.reuse` | non-enumerable deprecated getter `scope` returning the same frozen object |
| `DeriveOptions` | `ReuseConstraints` | type alias, deprecated |
| `ScopeTarget` | `ReuseTarget` | type alias, deprecated |
| args record `{ …, scope }` | `options: { reuse }` | deprecated overload: an args record whose `scope` key is present (typed as required in the overload so the two forms never overlap) is normalised to `options.reuse`; giving both → `TypeError` |
| error text `fresh targets inactive …` | unchanged | — |

- Source: `packages/core/src/descriptors.ts` (`EntryDefinition`, `EntryDescriptor`, `DeriveOptions`, `ScopeTarget`, `EnvHandle`, `SynaRuntime`, `BoundEntry`, `EntryParameters`), `definition.ts` (`defineEntry`, reserved ids), `runtime.ts` (`internalDeriveEntry`, `EnvImpl.enter/run/check/explain/derive`, `RuntimeImpl`, `createBoundEntry`, argument normalisation), `internal/entry-planner.ts` (`mergeScopeTargets`, `PlanEntryParameters`, signature — the internal signature key text `scope` stays so plan-template keys do not change), `internal/runtime-model.ts` (`ScopeTargetSet` stays internal).
- Tests: `core.test.mjs` (3), `contracts.test.mjs`, `hardening.test.mjs` (2), `v04-corrections.test.mjs`, `v04-regressions.test.mjs`, `v05-cache-cleanup.test.mjs`, `v05-audit-planning.test.mjs` (2), `v05-planner.test.mjs` (K03 derive), `reference-planner.test.mjs` (uses `scope: { fresh }` in args); new `v06-r1-reuse.test.mjs` (alias equivalence: same plan, same explain, same errors, both-given rejection, reserved ids); `type-tests/api.ts` (deprecated forms compile, `@ts-expect-error` for `scope` inside `EntryParameters`).
- Docs: `API_REFERENCE.md` (Entry definition, `enter/run/check/explain`, `derive`), `SEMANTIC_MODEL.md` (wording of "scope" where it means the fresh/share constraint), `PACKAGE_AUTHORING.md`, README example (already in new names).
