# Changelog

## 0.5.0

Semantics (see docs/SEMANTIC_CHANGES_V05.md and docs/MIGRATION_V04_TO_V05.md):

- `load()` is a plain Promise. Removed the setup completion barrier, AsyncLocalStorage strong-load tracking and the immediate `CIRCULAR_MATERIALIZATION` verdict. Pending waits are reported by a configurable initialization deadline (`INITIALIZATION_TIMEOUT`) with observed pending loads and a suspected load-call cycle as an observation, not a proof.
- Attempts and waiters: one attempt per slot at a time; `load({ signal })` ends only the caller's wait (`LOAD_CANCELLED`); timed-out attempts block overlapping attempts (`UNSETTLED_ATTEMPT`); late results are discarded, cleaned up and reported through `diagnostics.onEvent`; disposal reports never-settling attempts instead of claiming a clean close.
- Removed activation transactions and fake-Ready children. A Service-owned `BoundEntry` requires a Ready owner (`OWNER_NOT_READY`); worker worlds are started by the host after the root is Ready.
- Parent-only canonical-slot reuse with a fixed point over the reverse dependency graph; persistent lineage anchors re-attach only when every dependency slot matches, otherwise `LINEAGE_UNIQUENESS_CONFLICT` with the full chain. A brute-force reference planner is checked against production on seeded random graphs.
- `InputRef.read()` returns the payload as provided (Promise, thenable, function, undefined preserved); `InputRef.load()` deprecated. `loadAll()` accepts Service refs only.
- Private resolution realms: a Service-owned Entry resolves exact and range roots inside the owner's exact closure; Contract discovery stays public.
- `override(Source, Fake)` compiles into an internal `CompiledService` (Source identity, Fake executable manifest) used by every resolution path; decision table documented.
- `explain()`: inherited/new/forked counts for Services, Inputs and synthetic nodes, eager-to-start, choices, missing parameters and per-node cause paths. Planning search budget (`PLANNING_BUDGET_EXCEEDED`).
- `C.all` is the recommended same-Env collection; `C.selector` is a deprecated minimal compatibility surface.
- npm `semver` replaces the hand-written parser; ranges are validated at definition time; admitted prereleases participate in ranges.

Fixes from the independent audits (docs/AUDIT.md; regression tests `packages/core/tests/v05-audit-lifecycle.test.mjs`, `v05-audit-planning.test.mjs`, `apps/hyla-mini/tests/audit-app.test.mjs`):

- Core lifecycle: disposal is bounded by `disposal.graceMs` for running attempts too (no more waiting out a 30 s or infinite deadline); the stop signal is broadcast to the whole subtree before anything is awaited and sibling subtrees close concurrently; an Env with an abandoned attempt stays `disposing` until the late result is cleaned up; `onDispose()` registered after a deadline is honoured; disposal order follows dependencies through never-started slots; every `load()` caller gets its own Promise; an already-aborted `signal` starts nothing.
- Core planning: `explain()` lists missing Inputs/Bindings required deep in the graph; candidate-independent failures keep their own code instead of `UNSATISFIABLE_TOPOLOGY`; plan-template keys carry a digest of the parent signature (verified on hit) instead of the whole signature.
- Hyla-mini: SiteEnvs rotated during creation are closed, `invalidate()` uses a per-tenant generation, acquire retries are time-bounded; page cache keyed by a store content version; HTTP handlers answer 400 to unparsable targets and never echo internal errors (`onError` hook); fast-failing creations share one attempt (`SITE_CREATION_BACKOFF`); pool ended once on failed setup; static builder only removes files from its own manifest and refuses foreign directories; worker `stop()` during `start()`; authenticator interface checked at site creation; startup touches the backend; `close()` returns the unreleased-lease report; domain claims validated at save time, conflicts disable only the host.
- Orchestrator: `close` event, SIGTERM before SIGKILL, `todo`/`cancelled` count as not run, `<root>`-relative commands, provenance captured first, working-set written into the run directory, release hashes in `validation/v0.5-release/SHA256SUMS.txt`.

Fixes from the third review round (docs/AUDIT.md "Third review round"; regression tests `packages/core/tests/v05-review-lifecycle.test.mjs` R-5, `v05-cache-cleanup.test.mjs` R17 anchors, `v05-realms-override.test.mjs`, `v05-explain.test.mjs`):

- Core: a `Family.range()` reference carries its origin revision, so a Family referenced only by range resolves in the owner's private realm; a range loads the origin's Contract view (`ProvidedShape<Provides>`) and only revisions providing those Contracts are candidates (`INCOMPATIBLE_IMPLEMENTATION` otherwise). Plan templates are keyed by the lineage anchors (a stale hit is evicted and re-solved), so plans no longer depend on which lineage warmed the cache. A setup deadline that fires during the disposal grace no longer hides the attempt: the close reports `UNSETTLED_ATTEMPT` and the Env stays `disposing` until it settles. `check()`/`explain()` consume no Env id and `inspect().definitions` exposes the (bounded) registry sizes. Two physical copies of a revision with different `setup` bodies are a `DUPLICATE_DEFINITION` instead of first-wins. `preload()` is deprecated.
- Hyla-mini site manager and host: a redundant reservation hands its unit to the next waiter (no third acquirer starves); rotation is monotonic (a stale configuration read joins the newer SiteEnv instead of draining it; an `invalidate()` during a capacity wait is honoured); lease purposes are a capacity policy (`reservedForRequests`, default 1 when the capacity is at least 2: builds and background work never take the last unit, waiting requests go first; `stats().waitingByPurpose`); the maintenance loop is supervised (state `failed` with `lastError`, world released, reported through `close()`, restartable; `start({ domains })` reloads the domain table each tick); `createHylaApp()` also budget-checks one request from a synthetic site world and creates the manager at startup; `close()` is idempotent and reports manager shutdown errors; the domain table reloads on an unknown host at most once per `domainRefreshMinIntervalMs` so a tenant saved after startup is served without a restart; `normalizeDomain` strips a trailing dot and IDNA-encodes. Regressions in `apps/hyla-mini/tests/site-manager.test.mjs` (S2/S5/S6), `audit-app.test.mjs` (S4/S9), `preflight.test.mjs` (S8), `review-app.test.mjs` (S7).
- Hyla-mini caches, rendering and configuration: the page cache is bounded per SiteEnv (`siteManager.pageCacheMaxEntries`), single-flight and never keeps a failed render; concurrent content-version and configuration reads are coalesced; the pipeline cache is a bounded LRU keyed by (trust, recipe); factory sharing is proven by per-instance tokens (`factoryInstances()`; `factorySetupCounts` is frozen and deprecated); recipes carry a trust level (`build(document, { trust })`): comments are built `untrusted`, which forces raw HTML off and ends the pipeline with a factory declaring the `sanitizer` role, so a stage registered after the site's sanitizer cannot emit script; site configurations are validated on save and on read (`SiteConfigError`; `isSafeHref`, `isCssColor`), the renderer keeps fallbacks, malformed cookies are anonymous; end-to-end request latency is reported (not budgeted) by `benchmarks/hyla-request-latency.mjs`. Regressions in `render.test.mjs` (R2/R3/R4), `review-app.test.mjs` (R-2b), `audit-app.test.mjs` (R3/R4), repository conformance, `filesystem.test.mjs`, `postgres.test.mjs`.
- Hyla-mini static output: the builder renders the whole site into memory from one content version (retried while the version moves, `BUILD_CONTENT_CHANGED` when it never settles, nothing written), then atomically replaces new files, removes stale ones and writes the manifest last with `contentVersion`; one build per directory at a time (in-process mutex and `.hyla-build.lock`, stale locks taken over, live ones `BUILD_LOCKED`); the output directory is resolved and nothing below it may be or cross a symbolic link (`UNSAFE_OUTPUT_DIR`, checked before the first write); the static server resolves its root and follows no link. `StaticBuildError` carries the code. Regressions `audit-app.test.mjs` F-AP-08b/F-AP-08c; archived static-export probe updated for D28/I-77.
- Hyla-mini backends: posts are identified by `(tenantId, id)` on PostgreSQL too (composite primary key, single-column keys migrated in place); every mutation and its content-version bump are one unit of work (a transaction per public mutation on PostgreSQL; a `content.version.pending` marker on the filesystem, settled by the next read after a crash); domain ownership is decided by a `domains` row per normalized host under advisory locks (PostgreSQL) or a store-wide lock inside the tenant lock (filesystem), so concurrent claims have exactly one winner; the pool destroys a connection only on connection-level errors (`isConnectionError`, `stats().removed`) and leased clients no longer raise unhandled error events. Regressions in the repository conformance suite (same id in two tenants; concurrent claims, five rounds; the vacuous revision assertion fixed), `postgres.test.mjs` (schema key, legacy migration, trigger-refused bump rolls back everything, pool policy) and `filesystem.test.mjs` (leftover marker).
- Delivery: the Hyla-mini demo requests through `node:http` with the tenant's host and fails (exit 1) unless every cell answers 200 with the tenant's page; the gate asserts the demo output (`expectStdout`), reports `distinctTests` / `rebuildTests` next to total executions, and VALIDATION says how many cases ran twice in the rebuilt copy and points at the run's `SHA256SUMS.txt` instead of copying hashes; CI runs the demo and a `release-gate` job that uploads the archives, manifest and validation directory (written and checked locally, not yet run in the cloud).

Fixes from the independent re-audit of the third round (docs/AUDIT.md "Independent re-audit of the third round"; regression tests `packages/core/tests/v05-audit3-lifecycle-planning.test.mjs`, the audit-3 cases of the application, backend and conformance suites, `scripts/tests/*.test.mjs`):

- Core: selector candidate Entries are cached per physical revision descriptor (two Runtimes sharing a Contract no longer contaminate each other); a drifted copy of a definition is `DUPLICATE_DEFINITION` on a plan-template hit and from `check()`/`explain()` too; the unsettled-attempt ledger holds attempts strongly, so an attempt whose Env handle was dropped is still closed as unreachable with its cleanups run; dependency sites resolve in key order (plans do not depend on how a `requires` literal was written or on admission order); ledger states `rolling-back` and `settling`, `runtime.dispose()` waits the grace for settling cleanups, close reports name the phase; `run()` keeps a successful result on the close error (`error.result`); planning ids are numbered apart (`check-slot-N`). Documented: the close bound is one grace per tree level; an internal range origin is not a public-realm candidate.
- Hyla-mini site manager and rendering: a closing SiteEnv frees its key at once (no configuration-read spin, no `SITE_CAPACITY` with capacity free); an acquirer evicts idle Envs only when that makes it servable; a creation cut short by `shutdown()` is `SiteManagerClosedError` with the Runtime's error as `cause` and counts as no failure; one deadline bounds the whole acquire; the untrusted sanitizer gets a fresh plugin identity per configuration and the builder verifies the appended pass (a merging sanitizer factory is refused); `isSafeHref` refuses backslash spellings; only a manifest this builder wrote for this tenant is a previous build (`BAD_MANIFEST` otherwise); static builds render from the listing they hold (`SiteContext.renderPostPage`).
- Hyla-mini backends: a unit of work whose COMMIT answered `ROLLBACK` is `TransactionAbortedError`; domain conflicts are checked before the tenant's own rows are deleted; every PostgreSQL unit of work takes the per-tenant advisory lock (overlapping saves and same-tenant units of work serialize, no orphaned domain rows, no deadlock); `lock_timeout` (`lockTimeoutMs`) bounds lock waits; re-entering a tenant's public repository inside its unit of work is `TransactionReentrancyError` on both backends; the transaction repository serializes its own calls; pool disposal is bounded (`PoolClosedError`, `closeTimeoutMs`, `PoolCloseTimeoutError`, `PoolStats.leased/waiting`); the domains back-fill runs once with the table's creation and tolerates malformed rows; two files with one post id (a crash inside a rename) are one post and the surplus copy is removed by the next save or delete; NUL is refused before any write on both backends; `listTenants()` is the union over all tenant tables. Documented: filesystem durability is a process-crash boundary (no fsync).
- Delivery: gate steps run in their own process groups under a bounded timeout policy (`scripts/lib/step-runner.mjs`, tested by `npm run test:scripts` and the `gate-self-tests` step); `scripts/pg-test-cluster.mjs with` forwards signals to its command and stops the cluster; the four core demos assert their results and print `demo: OK`, required by the `demos` step; the manifest records the PostgreSQL server it ran against (`environment.postgres`) and how the run compares with the one it replaced (`previousRun`), both rendered by `scripts/validation-doc.mjs`; "three-cell demo" wording; `work/v05/` stated as repository-only.

Fixes from the second review round (docs/AUDIT.md "Second review round"; regression tests `packages/core/tests/v05-review-lifecycle.test.mjs`, `apps/hyla-mini/tests/review-app.test.mjs`):

- Core: a failed rollback is final (`ROLLBACK_FAILED` on every later `load()`, also under `retry-on-next-load`); a caught `LOAD_CANCELLED` never leaves an unhandled rejection behind; the bounded close detaches the Env from the tree and the Runtime's registries (its parent no longer waits for it, `inspect()` no longer counts it) while its state stays `disposing` until the abandoned attempts settle; those attempts are held weakly in `inspect().unsettledAttempts`, closed as `attempt-unreachable` when their setup Promise is garbage-collected, and reported again by `runtime.dispose()`; `UNSETTLED_ATTEMPT` names the dependency slots an abandoned attempt may still use (closed in the normal order: the model has no revocation, documented as inherent).
- Hyla-mini: a SiteEnv whose creation fails after it was entered is closed; a closing SiteEnv keeps its unit of capacity until its close settles (`disposing` records, FIFO grants); the page cache reads the content version before the content; background closes never reject (`onDisposalError` hook, `stats().disposalFailures`); `close()` returns `{ unreleasedLeases, unsettledAttempts, errors }` instead of rejecting.
